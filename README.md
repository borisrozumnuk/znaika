# Znaika

Flutter-прототип офлайн-заметок по встречам для macOS (Apple Silicon, 14.2+),
аналог Google Foresight с поддержкой русского. Всё работает локально, модели
встроены — ничего отдельно устанавливать не нужно.

**Запись → расшифровка → заметки:**
1. `packages/meet_capture` — Swift-плагин: системный звук (Core Audio Process Tap)
   и микрофон (Core Audio IOProc) в раздельные `system.wav` / `mic.wav`, 16 кГц.
   Код из `../capture-proto`.
2. `lib/live_transcriber.dart` — **расшифровка на лету**: плагин отдаёт звук обоих каналов
   (16 кГц, 10 раз в секунду), в фоновом изоляте Silero VAD режет поток на фразы, каждая
   законченная фраза сразу уходит в GigaAM v3 (`sherpa_onnx` 1.13.8). Реплика появляется
   через ~0,6 с после того, как её договорили. `lib/transcriber.dart` — те же модели
   по готовым файлам (запасной путь, если расшифровка на лету не поднялась).
3. `packages/litert_lm` + `lib/summarizer.dart` — своя Dart FFI-обёртка над C API
   LiteRT-LM v0.17.1 (как у Foresight) и Gemma 4 E4B на GPU. Две выжимки:
   «Кратко / Обсуждение / Решения» и «Задачи / Открытые вопросы».

**Интерфейс** — `macos_ui` 2.2.2 + `macos_window_utils` 1.9.1: окно с прозрачным заголовком
и боковой панелью на системном материале (`NSVisualEffectView`), тулбар, кнопки, индикаторы
и типографика macOS. Светлая/тёмная тема — как в системе (`ThemeMode.system`), выделение —
системным акцентным цветом, стандартные элементы на русском (`flutter_localizations`).
Вид соответствует macOS 15: Liquid Glass из macOS 26 во Flutter пока недоступен.
Файлы: `main.dart` (запуск, окно, тема), `home_page.dart` (окно и боковая панель),
`recorder_page.dart`, `meeting_view.dart`, `setup_page.dart`, общие элементы — `ui.dart`.
Вёрстка проверяется `test/ui_test.dart`: все экраны в светлой и тёмной теме, окно 760×520
и 1280×800, тест падает на исключениях и переполнениях.

**Список встреч.** Слева — прошлые встречи (`lib/meetings.dart`): заголовок и мельче
локальные дата и время («Сегодня, 02:18»), сверху самые новые. По клику справа
открывается выжимка (`lib/meeting_view.dart`, простой рендер Markdown) и свёрнутая
расшифровка; экран записи при этом не пересоздаётся — запись продолжается.
Метаданные — `meeting.json` в папке встречи: `startedAt` (локальное время начала),
`title` (Gemma придумывает 3–7 слов по выжимке), `durationSeconds`. У старых записей
без `meeting.json` дата берётся из имени папки, заголовок — из первой фразы выжимки.

**Действия со встречей** — в тулбаре просмотра встречи и в меню «Встреча» строки меню
macOS (`PlatformMenuBar`): «Новая запись» ⌘N, «Переименовать» (или двойной клик по заголовку;
Enter/щелчок мимо — сохранить, Esc — отмена), «Экспортировать…» ⌘E (Markdown через стандартную
панель «Сохранить», имя «ГГГГ-ММ-ДД Заголовок.md»), «Скопировать заметки» ⇧⌘C, «Удалить встречу» ⌘⌫ (с подтверждением; папка уходит в Корзину). Корзина
и панель сохранения — канал `znaika/files` в `macos/Runner/MainFlutterWindow.swift`.

**Поиск.** Поле «Поиск» вверху боковой панели: по заголовкам, выжимкам и расшифровкам,
по мере ввода (пауза 200 мс). Индекс — FTS5-таблица `meetings_fts` в той же базе
(схема версии 2, миграция с версии 1 создаёт таблицу, `sync()` заполняет её). У FTS5 нет
русской морфологии, поэтому слова запроса обрезаются до основы и ищутся по префиксу
(«пятница» → `"пятниц"*`), все слова обязательны, «ё» = «е». В результатах — фрагмент
текста с выделенным совпадением. Тесты — `test/search_test.dart`.
`MacosSearchField` не вызывает `onChanged` при очистке поля, поэтому слушаем контроллер.

**Хранение.** Папка встречи — основное хранилище (звук, `transcript.md`, `summary.md`,
`meeting.json`). Список читается из индекса в SQLite — `znaika.sqlite` в Application
Support, `drift` 2.35.0 (`lib/database.dart`, таблица `meetings`). При запуске
`MeetingStore.sync()` сверяет базу с папками: новые добавляет, исчезнувшие и без звука
удаляет; после записи встреча вносится сразу. SQLite собирается в приложение пакетом
`sqlite3` 3.6.0 (хук скачивает сборку из релиза sqlite3.dart и сверяет SHA-256).
После правки `lib/database.dart`: `dart run build_runner build`. `analyzer` закреплён
на 14.4.0: с 14.5.0 `build_runner` 2.16.1 не собирается.

**Черновик фразы.** Пока фраза звучит, сказанное с её начала перераспознаётся GigaAM
примерно раз в секунду (не чаще, чем вдвое дольше прошлого распознавания) и показывается
серым курсивом с «…»; конец фразы заменяет черновик окончательной репликой. Черновик «Я»
скрывается, пока звучит черновик собеседников (это эхо из динамиков).

**Собеседники по голосам** (`lib/speakers.dart`). Для каждой законченной реплики канала
собеседников считается отпечаток голоса (3D-Speaker ERes2Net, VoxCeleb, 26 МБ) и сравнивается с уже
известными голосами по косинусному сходству: ≥ 0,55 — тот же «Собеседник N» (его отпечаток
уточняется), меньше — новый; реплики короче 1,5 с нового собеседника не заводят. То же — при
расшифровке файлов. Без модели — одна метка «Собеседники». Модель и порог выбраны замером
**на русской речи** (VoxForge RU: 9 дикторов, 199 фраз, пары из разных сессий): EER — ERes2Net
1,4%, TitaNet small 1,6%, CAM++ zh+en 3,2%, WeSpeaker ResNet34 10,8%; моделирование 300 встреч
по 2–5 дикторов тем же алгоритмом при пороге 0,55 — 99,2% реплик подписаны верно, число
собеседников угадано в 90% встреч. В приложении встреча из 12 фраз трёх русских дикторов
подписана без ошибок. Синтезированные голоса macOS для такой проверки не годятся.

**Эхо в микрофоне.** Если звук идёт через динамики, микрофон слышит собеседников.
`lib/echo_filter.dart` убирает реплику «Я», если рядом по времени (±1 с) есть реплики
собеседников, содержащие ≥60% её слов (сравнение по первым 5 буквам: окончания в эхе
часто искажены). Работает и в окне во время записи, и в итоговой расшифровке.
Тесты — `flutter test test/echo_filter_test.dart`.

## Модели
Приложение само скачивает их при первом запуске в
`~/Library/Application Support/local.experiments.znaika/models/` (экран «Подготовка
Znaika», `lib/setup_page.dart`). Список с адресами и SHA-256 — `lib/model_manifest.dart`:

| Пакет | Файлы | Размер | Откуда |
|---|---|---|---|
| Детектор речи | `silero_vad.onnx` | 644 КБ | релиз k2-fsa/sherpa-onnx на GitHub |
| Распознавание речи | GigaAM v3: encoder/decoder/joiner/tokens | 232 МБ | HF `csukuangfj/…giga-am-v3…`, коммит `a6039be` |
| Различение собеседников | `3dspeaker_speech_eres2net_sv_en_voxceleb_16k.onnx` | 26 МБ | HF `csukuangfj/speaker-embedding-models`, коммит `0743f30` |
| Заметки | `gemma-4-E4B-it.litertlm` | 3,7 ГБ | HF `litert-community/gemma-4-E4B-it-litert-lm`, коммит `2eee7ac` |

Загрузчик (`lib/model_downloader.dart`, фоновый изолят через `lib/model_manager.dart`):
докачка через HTTP Range в `файл.part`, редиректы вручную (чтобы Range дошёл до CDN),
переподключение при зависании (30 с без данных), SHA-256 по ходу загрузки и переименование
только при совпадении, кэш проверенных файлов `.verified.json` (размер + время изменения),
проверка свободного места. Маленькие модели качаются первыми: «Начать работу» доступна,
как только готова расшифровка; Gemma докачивается в фоне (прогресс внизу списка встреч),
выжимка при необходимости ждёт её. Тесты — `test/model_downloader_test.dart`
(локальный сервер: обрыв, зависание, сервер без Range, неверная сумма, отмена, порча файла).

Пути берутся через `path_provider`: данные — `getApplicationSupportDirectory()`,
кэш скомпилированных GPU-ядер Gemma (~2 ГБ, пересоздаётся сам) —
`getApplicationCacheDirectory()`, то есть `~/Library/Caches/local.experiments.znaika/litert-lm`.
Старый кэш ранних сборок (`Application Support/.../cache`) удаляется при запуске.

## Сборка и запуск

Коротко — через `make`: `make` (релизная сборка), `make run` (собрать и открыть),
`make test` (анализатор и тесты), `make zip` (zip на рабочий стол), `make setup-screen`
(экран первого запуска), `make clean`. Подробно — ниже.
```bash
flutter build macos --release      # или flutter run -d macos
open build/macos/Build/Products/Release/Znaika.app
```
При первой записи macOS спросит у приложения доступ к микрофону и к записи
системного звука.

Перенести на другой Mac: `scripts/build_zip.sh` (`--test` — сначала анализатор и тесты)
собирает релиз, проверяет подпись и кладёт `Znaika-<версия>-<дата>.zip` на рабочий стол;
в конце печатает, как открыть его на другом Mac.

## Самопроверка без интерфейса
```bash
APP=build/macos/Build/Products/Release/Znaika.app/Contents/MacOS/Znaika
ZNAIKA_SELFTEST=10 $APP           # записать 10 с, расшифровать, вывести
ZNAIKA_TRANSCRIBE=<папка> $APP    # расшифровать готовую запись
ZNAIKA_SUMMARIZE=<папка> $APP     # расшифровать и сделать выжимку
ZNAIKA_RESUMMARIZE=<папка> $APP   # выжимка по готовому transcript.md (как «Пересоздать заметки»)
ZNAIKA_IMPORT=<wav 16 кГц> [ZNAIKA_IMPORT_AT=<ISO>] $APP  # готовая запись → встреча
# звук из видео: ffmpeg -i x.mp4 -vn -ac 1 -ar 16000 -c:a pcm_s16le x.wav
ZNAIKA_FULL=1 ZNAIKA_SELFTEST=20 $APP  # запись + выжимка + заголовок, как по кнопке
ZNAIKA_DOWNLOAD=60 $APP           # проверить модели, качать 60 с, пауза, вывести прогресс
ZNAIKA_ASK='Что решили по релизу?|А сроки?' $APP  # чат по встречам: вопросы через «|», вывести ответы
# экран загрузки моделей, даже если всё скачано (обычный запуск окна, не самопроверка):
open -n --env ZNAIKA_SHOW_SETUP=1 build/macos/Build/Products/Release/Znaika.app
```
Тестовая встреча: `../asr-proto/samples/meeting-test` (скопируйте `mic.wav` и
`system.wav` в отдельную папку).

## Проверено (2026-10-13, MacBook Air M3, 16 ГБ, macOS 26.6)
- Расшифровка на лету: реплика появляется через 0,6 с после конца фразы; после остановки
  хвост дорасшифровывается за 0,4 с, итог совпадает с показанным на лету.
- Запись: оба канала синхронны, речь из динамиков распознаётся.
- Расшифровка 76-секундной встречи — 4,1 с; текст совпадает с Python-версией
  (кроме двух знаков препинания).
- Выжимка — 27,6 с в release (с кэшем GPU-ядер), 32 с при первом запуске;
  процесс занимает ~4 ГБ памяти.
- Release-сборка 142 МБ без моделей.

## Устройство `packages/litert_lm`
- `macos/litert_lm/CLiteRTLM.xcframework` — `CLiteRTLM_mac.xcframework` из релиза
  LiteRT-LM v0.17.1, урезанный до arm64 (`lipo -thin`). Заголовки лежат
  в `Headers/CLiteRTLM/`: в корне `Headers` их `module.modulemap` конфликтует
  с таким же у sherpa-onnx («Multiple commands produce …/include/module.modulemap»).
- `StreamShim.swift` — прослойка потокового ответа: C API вызывает колбэк из своего
  потока, и кусок ответа живёт только во время вызова, поэтому куски копируются
  в очередь, а Dart забирает их опросом.
- `lib/litert_lm.dart` — FFI к C API: `LlmEngine.load`, `countTokens`, `generate`
  (поток строк; отмена подписки останавливает генерацию).
- На GPU модель считается во **float32**: во float16 (по умолчанию) Gemma на входе длиннее
  ~1500 токенов путает цифры и слова, а на ~4000 начинает повторять символы. Из-за float32
  контекст 8192 (с 16 384 на 16 ГБ запросы виснут по таймауту LiteRT-LM), расшифровка
  режется на части по 5000 токенов.

## Запуск записи (важно для macOS 26)
- Запуск/остановка — на фоновой очереди, а не на главном потоке; если устройство
  не стартовало за 10 с, приложение сообщает об ошибке вместо зависания.
- Микрофон стартует первым, системный звук вторым; дорожки выравниваются тишиной
  по общему моменту старта. Подробности и причины — в `../capture-proto/README.md`.

## Ограничения прототипа
- Песочница выключена: модели и dylib грузятся из произвольных путей.
- Сборка только arm64 (`ARCHS = arm64` в `macos/Runner/Configs`).
- Имя собеседника сначала подставляется в заметки без склонения («вернуться к Анна»);
  склонение и род исправляет «Пересоздать заметки» (Gemma, ~30 с на минутную встречу).
- Gemma 4 E4B иногда добавляет лишнюю задачу (вопрос принимает за поручение) и не всегда
  подписывает задачи именем собеседника.
- Ad-hoc подпись меняется при каждой сборке, и TCC может заново спрашивать
  разрешения; для стабильности нужен сертификат разработчика.
